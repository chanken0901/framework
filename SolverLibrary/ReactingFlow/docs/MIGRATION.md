# 独立化と詳細反応機構への移行計画

## 境界と整理方針

- NSE：既存単成分ソルバーとLandau–Lifshitz任意拡張。反応流を追加しない。
- ReactingFlow：混合気体の状態・熱力学・輸送・反応・反応流CFDを所有する。
- ScriptLibrary：環境生成・入力・実行・後処理の共通入口を維持する。
- 旧multicomponent：移行元として凍結ではなく保全。既存成果を削除せず、
  各移植先の同値テストが通った段階で参照先を切り替える。

現時点で旧反応流の全ファイルを移動していない。未コミットのCUDA成果も移行対象。
古いCMakeキャッシュや生成済みResearchRunsは勝手に更新しない。
既存のNSE/GPE/FFT関連の未コミット変更は今回の再設計と混ぜない。

R2内でも全形式を一度に有効化しない。対応していない速度形式を含む機構は
反応を省略せず、機構の読み込み段階で拒否する。
R1で必要な最初の検証機構を選定し、出典・ライセンス・単位系を固定する。
水素/空気の小規模機構を初期候補とするが、今回の構造サンプルはその代用ではない。

## 詳細反応用の契約

- 計算本体はNSE/GPEと同じFortranとする。R1/R2もFortran化済み。
- Python/Canteraは入力変換・比較検証だけ。旧実装は`reference/python/`に保全する。

- 外部YAMLと内部計算データを分離し、各セルで文字列やYAMLを処理しない。
- 内部単位はSI（kg、m、s、K、mol）。CFD無次元量との変換は一箇所に集約する。
- 化学種順序と反応順序を機構ごとに固定し、機構のハッシュを実行環境へ記録する。
- 化学種数・反応数を実行時サイズで扱い、GPUの固定長ローカル配列をそのまま移植しない。
- 生成エンタルピーを含む全エネルギーの定義を先に固定し、反応熱を二重加算しない。
- 逆反応速度は標準状態・濃度単位を明示した平衡定数から評価する。
- 反応次数・化学量論係数・第三体濃度は別々に保持する。
- 熱力学、速度評価、化学ODE、空間離散化、並列実行を別モジュールにする。
- CPUの基準実装とテストを先に確定する。化学セル毎の負荷差をMPI/OpenMP/GPU設計で扱う。

## 現状との差

既存コードにはNASA-7、輸送、一段反応、CFD、MPI、ノズル、GPU実装がある。
これらの存在を新ライブラリの詳細機構対応・検証済みとは見なさない。
現在の`mc_max_species=64`等の固定制限を単に増やす方法では詳細反応へ拡張しない。
再利用可能な数値処理は同値テスト付きで移植し、無関係なNSEのCMake分岐をコピーしない。

外部入力設計の参照：[Cantera YAML公式仕様](https://www.cantera.org/stable/yaml/index.html)。
R1はCantera 3.2.0経由の入力と同版での物性照合を実装した。
独自の全Cantera構文パーサーや全反応形式への互換性を保証するものではない。
R2では[KINETICS.md](KINETICS.md)の対応形式を独立評価する。未対応形式を含む機構は拒否する。

## デトネーションに向けた検証順序

R3の0D着火比較は必要条件であり、デトネーション計算の完成を意味しない。
R4では保存的な圧縮性多成分流、衝撃波捕獲、密度・圧力・種の正値性、
生成エネルギーを含む全エネルギー、反応積分との結合を検証する。
順序は0D着火 → 非反応衝撃波管 → 1D反応波 → 2Dセル構造 → 3Dとする。
1Dでは同じ機構・上流条件のCJ速度とZND構造を独立基準解と比較し、
誘導長・反応帯の格子解像度、時間刻み、化学許容誤差、分割誤差への収束を確認する。
過駆動波と自走波を区別し、境界反射による見かけの定常波を排除する。
2D/3Dと並列実行への移行はこの検証後に進める。現在これらは未検証・未実装。
